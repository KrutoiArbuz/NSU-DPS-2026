# Task_j2

Консольная программа принимает строки и сортирует общий список пузырьком в нескольких потоках.

## Функциональность

- Непустая строка добавляется в начало списка. Строки длиннее 80 символов разбиваются на части до 80 единиц UTF-16.
- Пустая строка выводит текущее состояние списка, в том числе во время сортировки.
- Можно выбрать собственный связный список или `ArrayList` в `Collections.synchronizedList()`.
- Число потоков и задержки внутри шага и между шагами задаются флагами.
- Режим `benchmark` сравнивает число шагов и время работы обеих реализаций.

## Запуск

Нужна Java 21. Команды выполняются из папки `Task_j2`. При первом запуске Gradle скачает зависимости.

1. Запустить программу с собственным списком:

```bash
./gradlew --console=plain run --args='--list linked --threads 2 --inside-ms 1000 --between-ms 1000'
```

2. Вводить строки, нажимая Enter после каждой. Для вывода списка нажать Enter на пустой строке.

Сортировка продолжается, пока открыт ввод. Ctrl+D в Linux завершает ввод и останавливает потоки. С задержками по одной секунде список сортируется постепенно.

Для библиотечного списка:

```bash
./gradlew --console=plain run --args='--list array --threads 2 --inside-ms 1000 --between-ms 1000'
```

### Флаги

| Флаг | Что задаёт |
| --- | --- |
| `--mode` | Режим `interactive` или `benchmark`, по умолчанию `interactive` |
| `--list` | Список `linked` или `array`, по умолчанию `linked`; используется в интерактивном режиме |
| `--threads` | Число сортирующих потоков, по умолчанию `2`; положительное число |
| `--inside-ms` | Задержка внутри шага под блокировкой в миллисекундах, по умолчанию `1000`; неотрицательное число |
| `--between-ms` | Задержка между шагами после освобождения блокировок в миллисекундах, по умолчанию `1000`; неотрицательное число |
| `--size` | Число строк для `benchmark`, по умолчанию `20`; неотрицательное число |
| `--passes` | Число полных проходов каждого потока для `benchmark`, по умолчанию `3`; положительное число |

## Проверка

```bash
./check.sh
```

Скрипт запускает все тесты и собирает приложение. Проверяются вставка в начало, разбиение длинных строк, вывод по пустой строке, полные проходы сортировки, число шагов и сохранность данных при одновременной вставке и сортировке. Также проверяется чтение списка между шагами и во время внутришаговой задержки у собственных узлов.

### Ручная проверка

Запустить программу с короткими задержками:

```bash
./gradlew --console=plain run --args='--list linked --threads 2 --inside-ms 10 --between-ms 10'
```

Ввести три строки:

```text
cherry
banana
apple
```

Подождать завершения проходов и нажать Enter на пустой строке. Ожидается:

```text
apple
banana
cherry
```

Добавить строку `apricot` и снова вывести список после сортировки. Она должна оказаться между `apple` и `banana`. Повторить проверку с `--list array`.

Для проверки разбиения ввести строку из 81 символа `a`, затем пустую строку. В списке появятся две записи: одна из 80 символов и одна из одного символа.

Сравнение двух реализаций:

```bash
./gradlew run --args='--mode benchmark --size 10 --threads 2 --passes 3 --inside-ms 10 --between-ms 2'
```

Программа сама заполняет списки и выводит две строки, `linked` и `array`. В каждой должны быть `theoretical=54` и `actual=54`: два потока делают по три прохода, каждый проход сравнивает девять пар. `seconds` показывает время работы в секундах, `ideal_lower_bound` показывает расчётную нижнюю оценку времени. Значения времени зависят от окружения. После измерения программа завершается сама.
