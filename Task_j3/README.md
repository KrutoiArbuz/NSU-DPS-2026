# Task_j3

HTTP-паук обходит ресурсы сервера, начиная с `/`, и выводит найденные сообщения в лексикографическом порядке.

## Функциональность

- Запросы выполняются параллельно в виртуальных потоках Java 21.
- Ссылки берутся из поля `successors` в JSON-ответе. Повторные ссылки и циклы не вызывают повторную загрузку одного URL.
- Одинаковые сообщения разных ресурсов сохраняются.
- Результат выводится в терминал или сохраняется в новый файл UTF-8.

## Запуск

Нужна Java 21. Команды выполняются из папки `Task_j3`. При первом запуске Gradle скачает зависимости.

1. Запустить сервер:

```bash
java -jar Task_J3-server.jar IvanIvanov
```

2. В другом терминале из папки `Task_j3` запустить паука:

```bash
./gradlew run --args='--server http://localhost:8080 --parallel 256 --timeout-seconds 30'
```

Для сохранения результата в файл:

```bash
./gradlew run --args='--server http://localhost:8080 --output messages.txt'
```

Существующие файлы не перезаписываются: для следующего запуска надо задать новый файл.

### Флаги

| Флаг                | Что задаёт                                                                  |
| ------------------- | --------------------------------------------------------------------------- |
| `--server`          | Адрес сервера, по умолчанию `http://localhost:8080`; обход начинается с `/` |
| `--parallel`        | Лимит одновременных запросов, по умолчанию `256`; положительное число       |
| `--timeout-seconds` | Таймаут одного запроса в секундах, по умолчанию `30`; положительное число   |
| `--output`          | Путь нового файла UTF-8; без флага сообщения выводятся в терминал           |

Таймаут относится к отдельному запросу. Общего ограничения времени обхода нет.

## Проверка

```bash
./check.sh
```

Скрипт запускает все тесты и собирает приложение. Проверяются аргументы запуска, циклы, повторные ссылки, сортировка сообщений, виртуальные потоки, лимит запросов и отмена при ошибке. HTTP-тесты используют локальный сервер и проверяют JSON, UTF-8, коды ответа, тип содержимого и таймаут.
