# Task_c6

Бронирует самый дешёвый доступный маршрут алгоритмом Дейкстры и списывает билеты всех его сегментов одной STM-транзакцией.

## Функциональность

- У каждого рейса ограниченный запас билетов в ref.
- Более дешёвый путь выбирается даже при большем числе пересадок.
- Если полного пути нет, возвращается ошибка, ни один сегмент не списывается.
- Сохраняются граф и интерфейсы `route`, `book-tickets`, `booking-future` из заготовки.
- Демонстрация измеряет перезапуски STM и покупки каждого из трёх клиентов.

## Запуск

Нужна Java 21. Команды выполняются из папки `Task_c6`. При первом запуске Gradle скачает зависимости.

```bash
./gradlew run
```

Без аргументов сравниваются промежутки между запросами 1, 10 и 50 мс. Для каждого опыта создаются новые ref билетов. Вывод содержит `:customers`, маршруты покупок, `:seconds` и `:restarts`.

Один выбранный промежуток:

```bash
./gradlew run -PappArgs='10'
```

Позиционный аргумент задаёт промежуток между запросами в миллисекундах.

## Стек

Clojure 1.12.0 на Java 21; самостоятельный проект со своим Gradle Wrapper, тесты через `clojure.test`.

## Проверка

```bash
./gradlew check
```

Проверяются дешёвый путь с пересадками, переход на более дорогой после исчерпания билетов, общие ref прямого/обратного индекса, отсутствие частичного списания, ограниченный запас под конкурентной нагрузкой и обслуживание всех клиентов демонстрации.
